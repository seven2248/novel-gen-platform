## 总结结论

当前实现是「4-Agent 函数链路 + Schema 骨架 + mock 测试」，还不是「可验收的系统闭环」。

按测试设计中的 8 条“必须达成”标准，关键缺口集中在：

1. 没有真实回写到 Story State Core
2. 没有状态变更事件日志落库
3. 没有连续 3-5 章的闭环执行能力
4. 没有 Truth Files（Markdown）导出能力

## 关键问题（按严重级）

### P0-1 主流程未回写 Story State Core（仅返回内存结果）

**现象**
- `run_main_flow` 只执行 planner/writer/reviewer/committer 并返回结果对象，没有持久化动作。

**代码证据**
- `packages/agents/src/main_flow.py:31`
- `packages/agents/src/main_flow.py:56`

**影响**
- 不满足“回写到 Story State Core”验收项。
- 章节状态不会累计，后续章节无法基于已提交状态迭代。

**对应验收项**
- 失败：成功标准第 5 条（回写到 Story State Core）

**建议修复**
- 在主流程中引入 repository 层，至少完成：
  - `create_chapter` / `update_chapter_state`
  - `save_chapter_content`
  - StoryState `chapters/hooks` 的原子更新

**影响**

**对应验收项**

### P1-2 Reviewer 与 Committer 契约不一致

**现象**
- `committer` 读取 `reviewer_output["used_hooks"]`。
- `reviewer_output.schema.json` 与 `run_reviewer` 均未定义/输出 `used_hooks`。

**代码证据**
- `packages/agents/src/committer.py:31`
- `packages/contracts/agent_io/reviewer_output.schema.json:35`
- `packages/agents/src/reviewer.py:47`

**影响**
- hook 支付/更新逻辑永远可能走不到。
- 契约驱动开发失效，后续集成时容易隐性故障。

**对应验收项**
- 间接阻塞：第 5 条（正确回写）

**建议修复**
- 二选一并统一：
1. reviewer 输出补充 `used_hooks` 字段并更新 schema；
2. committer 仅依赖 reviewer 已有字段，不读取不存在字段。
