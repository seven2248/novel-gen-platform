## 🔍 3 处值得补充的遗漏

### 遗漏 1：测试驱动开发（TDD）纪律性未被显式记录

我们在多轮评审中反复强调的一个核心工程原则是：

> **先写失败测试 → 运行确认失败 → 写最小实现 → 跑通测试 → Commit**

这个五步 TDD 节奏在 `v0.2.2` 实施计划里每个 Task 都有体现，但**交接包的 §11 操作守则里没有明确提及**。新 IDE 里的执行者可能会跳过"先写失败测试"这一步，直接开始写实现。

**建议在 §11 补充一条：**
> 8. 每个 Task 严格遵循五步 TDD 节奏：先写失败测试 → 运行确认失败 → 写最小实现 → 跑通测试 → Commit。不允许跳过"先运行失败"这一步。
