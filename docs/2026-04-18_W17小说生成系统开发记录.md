### Finding 4 — P1 — `story_state_repository.py` 提交操作缺少异常处理
**Severity:** P1
**File:** `services/api/app/repositories/story_state_repository.py`
**Problem:** `update_chapter_state` 中 `self.session.commit()` 无 try/catch，数据库错误会直接抛出
**Fix:** 将 commit 包裹在 try/except 中，失败时返回 `(None, False)`

同时新增两个 `_unchecked` 变体方法，消除调用方已有对象时的冗余查询：

```python
def update_chapter_state_unchecked(self, chapter: "ChapterState", new_state: str) -> "ChapterState":
    """Update chapter state without re-fetching — caller already holds the chapter object."""
    chapter.state = new_state
    chapter.version += 1
    chapter.updated_at = datetime.now(timezone.utc).isoformat()
    self.session.commit()
    self.session.refresh(chapter)
    return chapter

def save_chapter_content_unchecked(self, chapter: "ChapterState", content: dict, word_count: int | None = None) -> "ChapterState":
    """Save chapter content without re-fetching — caller already holds the chapter object."""
    chapter.content_json = json.dumps(content, ensure_ascii=False)
    if word_count is not None:
        chapter.word_count = word_count
    chapter.updated_at = datetime.now(timezone.utc).isoformat()
    self.session.commit()
    self.session.refresh(chapter)
    return chapter
```

**Status:** ✅ 已修复

## 三、第二轮同伴复核发现（2 项遗留问题）

### Peer-Finding 1 — P1 — 乐观锁仍存在 TOCTOU 假阳性

**文件：** `services/api/app/repositories/story_state_repository.py`

**问题描述：** 第一轮修复将判断条件从 `ch.version != expected_version + 1 or ch.state != new_state` 改为仅检查 version，但仍依赖 re-fetch 来验证 UPDATE 是否成功。当两个 writer 并发写入**相同的 target state** 时：

1. A 和 B 同时读取 version=0, state="not_started"
2. A 的 UPDATE 成功（version → 1, state="drafting"）
3. B 的 UPDATE `WHERE version=0` 匹配 0 行（version 已是 1）
4. B re-fetch 得到 version=1, state="drafting"
5. 仅凭 version=1 == expected_version+1 仍判定为成功 —— **假阳性**

**修复方案：** 以 `UPDATE` 语句的 `rowcount` 为唯一权威信号：rowcount=1 → 我的 UPDATE 命中；rowcount=0 → 版本被他人抢先修改，re-fetch 仅用于构造返回值。

```python
result = self.session.exec(stmt)
rowcount = result.rowcount  # 1 = 我的更新命中，0 = 被抢先
self.session.commit()

if rowcount == 0:
    ch = self.get_chapter(project_id, chapter_id)
    return ch, False
ch = self.get_chapter(project_id, chapter_id)
return ch, True
```

> **调试记录：** 最初尝试使用 `with self.session.connection() as conn` 读取 `rowcount`，发现 SQLite + SQLModel 的事务管理与其冲突，导致 `InvalidRequestError: This transaction is inactive`。最终确认 `session.exec(stmt).rowcount` 在 SQLAlchemy 2.x 下完全可用——在 session.exec() 返回的 CursorResult 上直接读取 rowcount 即可。

**相关测试：** 新增 `test_concurrent_writes_same_target_state_both_return_false` 覆盖该场景。

**Status:** ✅ 已修复
