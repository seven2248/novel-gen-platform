**决策**：修。

涉及方法：

**副作用**：DeprecationWarning 消失，所有 32 个测试继续通过。

### 决策 2：story_state 数据大小限制 10MB
**文件**：
- `services/api/app/routers/agent_runs.py`
- `services/api/app/routers/local_rewrites.py`

**问题**：story_state 是一个无约束的 `dict` 类型，客户端可以发送任意大的数据，有内存耗尽风险。

**决策**：加 10MB 上限。

**修复**：在 `MainFlowPayload` 和 `LocalRewritePayload` 中添加 Pydantic `field_validator`：

```python
@field_validator("story_state")
@classmethod
def check_story_state_size(cls, v: dict) -> dict:
    size = len(json.dumps(v, ensure_ascii=False).encode("utf-8"))
    if size > MAX_STORY_STATE_SIZE:
        raise ValueError(f"story_state exceeds 10 MB limit ({size} bytes)")
    return v
```

**行为**：超过 10MB 的请求返回 HTTP 422 验证错误。

### 决策 3：AI 生成接口加 10 分钟超时
**文件**：
- `services/api/app/routers/agent_runs.py`
- `services/api/app/routers/local_rewrites.py`

**问题**：调用 `run_main_flow()` 和 `run_local_rewrite()` 没有超时控制，AI 无响应时会无限挂起。

**决策**：加 10 分钟（600 秒）超时。

**修复**：
- 使用 `ThreadPoolExecutor` 提交任务，获取 `concurrent.futures.Future`
- 通过 `asyncio.wrap_future()` 转为 `asyncio.Future` 后用 `wait_for(timeout=600)` 包装
- 超时后调用 `afuture.cancel()` 取消协程，并通过 docstring 明确说明线程无法被强制终止

```python
_llm_pool = ThreadPoolExecutor(max_workers=4)  # 共享线程池，有界

@router.post("/main-flow")
async def create_main_flow_run(payload: MainFlowPayload):
    loop = asyncio.get_running_loop()
    future = _llm_pool.submit(run_main_flow, story_state=..., chapter_goal=...)
    afuture = asyncio.wrap_future(future)
    try:
        return await asyncio.wait_for(afuture, timeout=600.0)
    except asyncio.TimeoutError:
        afuture.cancel()
        raise HTTPException(status_code=504, detail="...")
```

**关键限制**：`asyncio.wait_for` 只能取消外层协程，无法强制停止已在线程中运行的阻塞调用。超时后线程被"抛弃"（不 join），但线程本身继续运行直到 LLM 调用返回。真正可取消的方案需要将 LLM 调用放到独立 subprocess 中或使用支持取消的 async LLM client。

**附注**：初版实现使用了 `asyncio.to_thread`，经同事评审发现同样问题，已统一改为上述方案。

### 决策 4：GET /projects 拆分为只读接口
**文件**：
- `services/api/app/routers/projects.py`
- `services/api/app/repositories/story_state_repository.py`

**问题**：原 `GET /projects/{project_id}` 实际上调用了 `get_or_create_project()` — 找不到项目时直接创建一个空项目。这不符合 REST 语义（GET 应该是只读）。

**决策**：拆成两个接口，GET 只读、POST 才创建。

**修复**：

1. 在 `StoryStateRepository` 中新增纯读取方法 `get_project()` 和真正的 upsert 方法 `upsert_project()`：
```python
def get_project(self, project_id: str) -> StoryState | None:
    """Read-only — returns None if not found, never creates."""
    return self.session.exec(select(StoryState).where(...)).first()

def upsert_project(self, project_id: str, title: str = "", genre: str = "", style: str = "") -> StoryState:
    """Create or update a project. If project exists, update its fields."""
    state = self.get_project(project_id)
    if state is None:
        state = StoryState(project_id=project_id, title=title, genre=genre, style=style)
        self.session.add(state)
        self.session.commit()
        self.session.refresh(state)
    else:
        if title:  state.title = title
        if genre:  state.genre = genre
        if style:  state.style = style
        self.session.commit()
        self.session.refresh(state)
    return state
```

2. `GET /projects/{project_id}` 调用 `get_project()`，找不到返回 404。
3. `POST /projects/{project_id}` 改用 `upsert_project()`，实现真正的 upsert 语义（之前 `get_or_create_project` 会在项目存在时忽略新值）。

### Review Fix 1：P1 — 超时线程泄漏（已修复）
**问题**：`asyncio.wait_for` 取消外层协程后，底层线程继续运行。反复超时导致线程堆积，拖垮服务。

**残留限制**：线程本身无法被强制停止，只能被"抛弃"。真正可取消需要 subprocess 隔离。

**修复**：新增 `upsert_project()` 方法，项目存在时真正更新字段。POST 改用 `upsert_project()`。

## 晚间：CE Review 复核 + 修复

### 背景

下午的三次 commit 合并后，对最新变更（上午 + 下午的 10 个修复）执行完整 CE review，共启动 6 个 reviewer：correctness、testing、maintainability、kieran-python、reliability、api-contract。

### 一、Review 发现的新问题（本次 review 引入，非上游遗留）

#### P1-N1：`loop = asyncio.get_running_loop()` 死代码（双确认）

**文件**：`agent_runs.py`、`local_rewrites.py`

**问题**：引入 `ThreadPoolExecutor.submit()` 时保留了这行代码，但 `asyncio.wrap_future()` 不需要显式获取事件循环。变量赋值后从未使用。

**修复**：
```python
# 删除：loop = asyncio.get_running_loop()
future = _llm_pool.submit(...)
```

#### P1-N2：`except Exception` 拦截 Pydantic 校验异常 → 返回 500 而非 422

**文件**：`agent_runs.py`、`local_rewrites.py`

**问题**：经 Python 行为验证确认——`except Exception` 会捕获 Pydantic `field_validator` 抛出的 `ValueError`（被包装为 `RequestValidationError`），导致本应返回 HTTP 422 的 Oversized Payload 错误变成 HTTP 500。

**验证路径**：
```
field_validator 抛出 ValueError
→ FastAPI 捕获并包装为 RequestValidationError（继承自 Exception）
→ except Exception 捕获
→ HTTP 500（而非 FastAPI 原生返回的 HTTP 422）
```

**修复**：
```python
except asyncio.TimeoutError:
    afuture.cancel()
    raise HTTPException(status_code=504, ...)
except ValueError:
    raise  # let FastAPI's native Pydantic/validation handler return 422
except Exception as e:
    raise HTTPException(status_code=500, detail=f"Agent run failed: {e!s}")
```

| `ThreadPoolExecutor.submit()` 阻塞事件循环 | **不是问题** | `submit()` 本身非阻塞，立即返回 Future；真正阻塞的是 worker 线程内的 `run_main_flow()`。这是已记录在 docstring 的架构限制 |
